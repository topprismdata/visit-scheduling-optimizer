## 一、业务背景

### 1.1 核心痛点：临时加店是常态而非例外

通过对全办 9,760 条真实打卡流水的逐条下钻分析，我们发现一个颠覆性事实：

> **现场拜访中，高达 17.5% ~ 37.7% 的打卡是突发临时新增门店（Ad-hoc Visits），全办平均 27.4%。**

一线业代在面对临时加店时，只能依靠个人记忆和直觉边走边看，导致严重的：
- **折返跑**：在同一条主干道上午打卡一次，下午又大老远折返打卡一次
- **跨区横跳**：在海珠与荔湾之间反复穿梭，单段骑行超过 10 公里
- **高里程**：全月 10 位业代累计骑行 **13,417.7 公里**，其中 58% 是无效冤枉路

### 1.2 Agent 动态调度的解决方案

`SalesVisitDispatchAgent` 通过三层机制实时护航：
1. **已打卡前缀冻结**：业代上午已走的店绝不倒流
2. **沿街走廊顺路投影**：将临时店嵌入当前剩余路线的最近通行弧段
3. **毫秒级接缝抛光**：仅对接缝做局部 2-opt，全流程 **< 3 毫秒** 响应

## 四、与月度日程优化（Layer 1）的关系

本报告对比的是 **Layer 2：单日动态执行优化**（Agent 在途插单），与 Layer 1（月度日程优化）互补：

| 对比维度 | Layer 1 月度日程优化 | **Layer 2 单日动态优化（本报告）** |
|---|---|---|
| 时间维度 | 月度（23 工作日） | 单日（毫秒级实时） |
| 核心问题 | 店→日怎么排？日内顺序怎么走？ | 临时插单怎么顺路消化？ |
| 算法 | ALNS v3 + CP-SAT + SDR 证书 | 走廊投影 + 前缀冻结 + 接缝抛光 |
| 基线 | TSP 日内重排 4,606 km | **人类实际走法 7,624 km** |
| 结果 | 3,859 km（额外 −41.5%） | **5,632 km（额外 −58.0%）** |
| 响应时间 | ~300 秒/线 | **< 3 毫秒/次** |

两层叠加效果：月度日程优化先降 41.5%，Agent 动态护航再在实际执行中降 58.0%，**双层合计使业代的真实骑行里程降低超过 70%**。
