# 0. 30 秒理解

SDR Exact 是上一代“顺序生成 + 集合选择”的组合优化方案。

它解决的问题：

> 在固定原始日历不变的情况下，生成多个日内路线候选，再通过集合划分选择组合，并用
> LP 松弛估计当前候选池质量。

流程：

``` mermaid
flowchart LR

A["Original Calendar"]

B["Multi-start Route Pool"]

C["SP Selection"]

D["LP Relaxation"]

A --> B
B --> C
C --> D
```

核心思想：

    多样化候选

    +

    组合选择

    +

    gap 分析

------------------------------------------------------------------------

# 1. 历史定位

SDR Exact 属于上一代组合层算法。

它固定：

    原始日历分配

只优化：

    同一天内部访问顺序

因此它回答：

> 在固定拜访分配下，通过更多路线采样和组合选择还能获得多少收益？

------------------------------------------------------------------------

# 2. 三阶段流程

## Stage 1：Route Pool Generation

函数：

    _gen_pool

生成：

    RoutePool

来源：

- 原计划；
- NN2opt；
- 多起点随机 NN2opt；
- 2opt 扰动。

每日期：

    约 K 条候选路线

目标：

增加顺序多样性。

------------------------------------------------------------------------

## Stage 2：Set Partitioning Selection

函数：

    _sp_solve

使用：

    CP-SAT SP

选择路线组合。

约束：

    每日期选择 1 条路线

    每店满足 freq

注意：

旧版本：

    无 Contract 闸

    无 R2′ 闸

因此已被：

    Contract-SP Final Gate

替代。

------------------------------------------------------------------------

## Stage 3：LP Relaxation

函数：

    _lp_lb

使用：

    GLOP LP

得到：

    pool LP value

计算：

    pool_gap_pct

重要：

它不是：

    global lower bound

而是：

    当前 route pool 内的 LP gap

------------------------------------------------------------------------

# 3. 为什么退役

SDR Exact 的退役不是因为思想错误，而是因为系统架构升级。

------------------------------------------------------------------------

## 原因 1：固定日历限制上限

SDR：

    日期分配固定

因此能力上限接近：

    Base

原因：

Base 已经使用：

    CP-SAT 精确日内排序

当排序已经最优时：

大量顺序采样必然被支配。

------------------------------------------------------------------------

## 原因 2：旧 SP 被 Contract-SP 替代

旧模型：

    集合划分
    +
    频次

缺少：

- 合同语义；
- R2′；
- phase。

新版：

    Contract-SP

统一承担组合层职责。

------------------------------------------------------------------------

## 原因 3：LP gap 被 CG/B&P 替代

SDR：

    有限 pool LP

只能回答：

> 当前候选池质量。

现在：

    Column Generation

    +

    Branch-and-Price

提供：

- 动态扩展变量；
- 更强 bound；
- 证书链。

------------------------------------------------------------------------
