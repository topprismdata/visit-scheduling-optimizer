# Base：构造式基准——原分配 + 精确日内排序

> 类别：构造式基准（Constructive Baseline）  
> 实现：`experiments/run_contract_matrix.py::base_schedule`  
> 研究矩阵角色：**对比基准（Baseline）**——所有引擎的公里数评价分母

------------------------------------------------------------------------

# 0. 30 秒理解

Base 解决的问题：

> 如果完全不改变原始拜访日历，只把每天内部访问顺序优化到最好，可以达到什么水平？

它不搜索。

它不改变：

- 哪天拜访哪家店；
- 合同分配；
- 日历结构。

它只优化：

> 固定日历下的日内路线顺序。

------------------------------------------------------------------------

------------------------------------------------------------------------

# 2. 它回答什么问题

Base 不是：

> 全局最优方案。

它回答：

> 在不改变业务分配的情况下，日内排序优化的理论收益是多少？

因此：

它隔离了两个因素：

    日历变化收益

    vs

    路线排序收益

# 5. 为什么使用 CP-SAT TSP

如果基线使用普通 heuristic：

例如：

- NN；
- 2-opt；

那么基线本身包含：

    排序算法误差

无法判断：

引擎收益来自：

- 改变日历；
- 还是只是排序更好。

因此 Base 使用：

    CP-SAT exact ordering

作为日内排序质量锚。

------------------------------------------------------------------------

必须记录：

    基线 A

    限时参考结果

    最优排序基线

# 10. 常见误区

## 误区 1

Base 是全局最优。

错误。

它固定：

    原日历

只优化：

    日内排序

------------------------------------------------------------------------

## 误区 2

Base 越低，说明业务计划越好。

错误。

Base 只说明：

    固定分配下路线效率

------------------------------------------------------------------------

## 误区 3

Base 注入所有算法。

错误。

研究矩阵：

Base 是：

    独立比较参照

------------------------------------------------------------------------
