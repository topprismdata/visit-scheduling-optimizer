# ALNS v4：稳定性权衡精修器（Incremental Reoptimization）

> 类别：元启发式增量重优化（Incremental Reoptimization Layer）  
> 实现：`algos/alns_v4.py`  
> 生产定位：**月度微调工具**（改动约 1~16 家店场景）  
> 核心职责：在现有计划基础上，以最小扰动换取业务改善

------------------------------------------------------------------------

# 0. 30 秒理解

ALNS v4 不是全量规划器。

它解决的问题：

> 已经有一个可执行计划，现在业务希望“小范围调整”，如何在里程、稳定性、工作量均衡之间找到合理折中？

优化目标：

\[ J = 里程 + 改动成本 + 工作量方差 \]

其中：

- λ 控制稳定性；
- μ 控制每日负荷均衡。

# 2. 为什么需要增量重优化

全量重规划的问题：

    新方案可能更优

    但业务接受成本很高

真实业务更常见：

    保持原计划稳定

    +
    少量调整

    +
    获得收益

因此：

ALNS v4 优化的是：

> 从当前方案出发的局部改善。

------------------------------------------------------------------------

# 3. 三目标权衡

## 3.1 里程

目标：

    减少总 km

------------------------------------------------------------------------

## 3.2 稳定性 λ

表示：

    每移动一家店

    至少需要多少里程收益

λ 越大：

    越贴近原计划

------------------------------------------------------------------------

## 3.3 均衡度 μ

惩罚：

    每日拜访量方差

μ 越大：

    越倾向平均分布

------------------------------------------------------------------------

# 4. 免费日内优化原则

重要规则：

    日内排序优化

    不算计划改动

即：

    Δ = 0
    Var = 0

只要降低里程：

直接接受。

这符合两层架构：

    日历稳定性

    和

    路线排序优化

    分离。

# 10. “Pareto”命名修正

ALNS v4 原名容易产生误解。

当前机制：

    weighted sum

即：

\[ J=f_1+f_2+f_3 \]

它：

不能声明：

    Pareto optimal

原因：

- 不维护非支配解档案；
- 不覆盖全部 Pareto front；
- unsupported solutions 可能遗漏。

真正多目标版本：

    mo_alns_v4

需要维护：

    non-dominated archive

# 12. 正确评价方式

不要问：

> ALNS v4 是否找到全局最优计划？

应该问：

> 在稳定性约束下，它能否以较小业务扰动获得可接受改善？

指标：

- km improvement；
- moved stores；
- objective J；
- workload variance。
