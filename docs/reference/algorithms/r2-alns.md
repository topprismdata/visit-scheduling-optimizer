# R2′-ALNS：合同同构局部搜索候选日历生成器

> 类别：元启发式候选生成器（Stochastic Local Search Layer）  
> 实现：`algos/r2_alns.py`  
> 研究定位：Layer1 日历层主力候选生产器  
> 核心思想：让搜索空间与合同可行域同构

------------------------------------------------------------------------

# 0. 30 秒理解

R2′-ALNS 解决的问题：

> 在业务合同允许的真实自由度内，寻找更优的跨日拜访日历。

它不是：

- 任意移动门店日期；
- 先生成大量非法方案再过滤。

它的核心设计：

> 每一个搜索 move 都天然符合 R2′ 合同语义。

原实现定位：

> Layer1 日历层主力引擎，在“整店换星期几 +
> 同星期几槽位轮换”的业务真实自由度上进行随机局部搜索。fileciteturn10file0L6-L8

# 2. 为什么需要 R2′-ALNS

传统局部搜索：

    移动门店日期

    ↓

    检查是否合法

问题：

大量搜索空间浪费在：

    必然非法

方案。

R2′-ALNS：

    合同语义

    ↓

    生成合法 move

    ↓

    搜索

因此：

搜索空间本身就是业务可行域。

------------------------------------------------------------------------

# 3. 搜索对象

R2′-ALNS 不直接搜索路线。

它搜索：

    门店
        ↓
    访问星期选择
        ↓
    合同槽位日期集合

例如：

原：

    Store A

    Monday

移动：

    Thursday

生成：

    Thursday 对应合同合法日期集

而不是任意日期。

# 6. Move Generation：合同同构邻域

核心：

    move_candidates()

流程：

    选择门店 c

    ↓

    枚举目标星期 w'

    ↓

    读取 contract + phase 对应槽位

    ↓

    生成候选日期集

因此：

移动天然满足：

- 周访；
- 双周；
- phase；
- 星期一致。

------------------------------------------------------------------------

# 7. 快速估价

搜索阶段不调用完整求解器。

使用：

    removal_gain

    +

    insertion_cost

基于：

    2-NN 三角关系

特点：

- 与访问顺序无关；
- 只依赖门店集合和距离矩阵；
- 平局按店号排序保证确定性。

------------------------------------------------------------------------

# 8. 接受机制

当前：

优先接受：

    delta < -1e-9

即：

改进方案。

同时：

    5%

概率接受变差方案。

目的：

避免：

    局部最优陷阱

------------------------------------------------------------------------

# 9. 终局精排

搜索结束：

如果：

    final_reroute=True

则：

逐日调用 CP-SAT 精确重排。

规则：

    只有 OPTIMAL 才接受

因此：

搜索阶段：

快速。

终局：

质量锚。

------------------------------------------------------------------------

# 10. 确定性设计

这是 R2′-ALNS 的重要工程约束。

搜索期：

禁止：

    CP-SAT

避免：

- 平局抖动；
- 不同运行发散。

保证：

    same seed

    ↓

    same search trajectory

# 13. 已知边界

## 13.1 没有全局最优证明

R2′-ALNS：

属于局部搜索。

因此：

    找到更好方案

    ≠

    证明最优

证明需要：

- sp-cg；
- branch-and-price。

------------------------------------------------------------------------

## 13.2 km 必须通过终闸

输出不能直接成为最终结果。

必须：

    R2′-ALNS

    ↓

    Contract-SP

    ↓

    Validation

------------------------------------------------------------------------

## 13.3 columns 精度不能污染

`metadata._columns`

必须保持：

    raw floating km

不能：

    round(3)

否则会污染：

- LP；
- B&P；

下界计算。

------------------------------------------------------------------------

# 14. 评价 R2′-ALNS 的正确方式

> 它是否在合同真实自由度内产生高质量候选空间？

指标：

- candidate quality；
- km improvement；
- pool contribution；
- SP final improvement。
