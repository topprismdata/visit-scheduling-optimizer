# HGS-PVRP：混合遗传搜索候选日历生成器

> 类别：元启发式候选生成器（Population-based Algorithm Layer）  
> 实现：`algos/hgs_pvrp.py`  
> 机制定位：Layer1 候选日历生产者  
> 核心特点：通过种群多样性探索日历 + 路线联合空间

------------------------------------------------------------------------

# 0. 30 秒理解

HGS-PVRP 解决的问题：

> 在大量可能的拜访日历和路线组合中，通过种群搜索发现高质量候选方案。

它与 ALNS v3 处于同一层：

``` mermaid
flowchart LR

    R2["R2′-ALNS"]
    A["ALNS v3"]
    H["HGS-PVRP"]

    Pool["Candidate Pool"]

    SP["Contract-SP Final Gate"]

    R2 --> Pool
    A --> Pool
    H --> Pool

    Pool --> SP
```

核心区别：

``` text
ALNS v3

单解轨迹搜索


HGS-PVRP

种群进化搜索
```

因此保留 HGS 的价值：

> 不是为了保证排名第一，而是提供不同搜索机制和多样化候选。

------------------------------------------------------------------------

# 1. 它解决什么问题

HGS-PVRP 是 Layer1 candidate producer。

它探索：

    日期分配

    +

    每日路线顺序

联合空间。

输出：

不是最终计划。

而是：

    候选日历
            ↓
    Contract-SP
            ↓
    最终选择

------------------------------------------------------------------------

# 2. 与 ALNS v3 的区别

|          | ALNS v3        | HGS-PVRP              |
|----------|----------------|-----------------------|
| 搜索状态 | 单个解轨迹     | 多个个体              |
| 核心机制 | destroy-repair | selection + crossover |
| 优势     | 快速局部探索   | 保持群体多样性        |
| 风险     | 局部收敛       | 种群管理成本          |

因此：

两者不是简单竞争关系。

它们提供：

> 不同搜索体制下的候选空间。

------------------------------------------------------------------------

# 3. 输入输出

## 输入

- `LineData`
- 日期集合 `D`
- `time_budget`
- `seed`

适配假设：

- 每日开放链；
- 每店出现次数满足合同频次；
- 可以跨工作日移动；
- 单日容量硬约束。

------------------------------------------------------------------------

## 输出

    AlgoResult
    (
     days,
     km,
     capacity_ok,
     metadata
    )

包含：

- 每日有序路线；
- 总距离；
- 容量状态；
- 搜索统计。

    _Ind

------------------------------------------------------------------------

# 6. 种群进化

## 6.1 偏差适应度

选择不是只看距离。

综合：

    rank(km)

    +

    rank(diversity)

避免：

    全部个体快速收敛到同一种方案

------------------------------------------------------------------------

## 6.2 交叉

采用：

日级均匀重组。

例如：

    child day1 = parent A

    child day2 = parent B

    child day3 = parent A

保持：

日期层结构。

------------------------------------------------------------------------

## 6.3 守恒修复

交叉可能破坏：

    每店访问次数

因此：

执行：

### 多了

按最小移除增量删除。

### 少了

按最小插入增量补充。

保证：

    visit count conservation

------------------------------------------------------------------------

# 7. Education：局部优化

每代执行短 SA：

    hot = 0.15

    单代 ≤12% 剩余时间

作用：

把遗传产生的新个体快速优化。

------------------------------------------------------------------------

# 8. 终局优化

best individual：

执行：

    daily two_opt

    30轮

作为最终 route polish。

# 11. 已知边界

## 11.1 不保证合同合法

HGS 可以产生：

- R2′违例；
- 合同违例。

必须经过：

    Contract-SP

    +

    check_contract

原文定义：

候选生产者输出最终仍需经过终闸。fileciteturn9file0L37-L39

------------------------------------------------------------------------

## 11.2 确定性弱于单解搜索

由于：

- population；
- deepcopy；
- 迭代顺序；

即使相同 seed：

route sequence 仍可能存在差异。

研究复现必须固定：

- worker；
- 顺序；
- 随机源。

------------------------------------------------------------------------

# 12. 共享组件边界

HGS 与 ALNS v3 共享：

- SA；
- two_opt；
- best_insert；
- worst_edge。

这些属于：

    OptiCore geometry primitives

因此实验分析时：

需要区分：

算法机制收益

vs

共享组件收益。

------------------------------------------------------------------------

# 13. 评价 HGS 的正确方式

不要问：

> HGS 是否直接得到最终最优计划？

应该问：

> HGS 是否提供了有价值、多样化、互补的候选空间？

评价：

- candidate quality；
- diversity；
- Contract-SP improvement；
- pool contribution。
