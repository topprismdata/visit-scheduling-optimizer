# R2′ 星期几一致契约：从业务规则到计划优化本体

> 类别：横切概念——业务主契约  
> 适用范围：所有日历层算法（R2′-ALNS / BP-Solo / SP-CG 的 r2_prime
> 模式）  
> 核心职责：定义“什么样的拜访日期安排才是合同意义上的合法计划”

------------------------------------------------------------------------

# 0. 30 秒理解

R2′解决的问题不是：

> 门店应该安排在哪一天？

而是：

> 如果一家门店选择了某个星期几，它是否应该在整个计划周期保持这个节奏？

一句话：

> 门店可以从周一调整到周四，但调整后整个月必须保持周四；禁止同一家店在不同星期几之间漂移。

例如：

合法：

    原：
    W1 周一
    W2 周一
    W3 周一
    W4 周一

    调整：
    W1 周四
    W2 周四
    W3 周四
    W4 周四

非法：

    W1 周一
    W2 周四
    W3 周一
    W4 周四

------------------------------------------------------------------------

# 1. 为什么需要 R2′

传统排班容易把问题理解成：

    某一天安排某一家店

但真实业务合同不是单次安排，而是节奏合同：

    合同
     ↓
    访问频率
     ↓
    周期节拍
     ↓
    固定星期模式

因此：

拜访计划不是一组独立日期，而是一种持续性的服务节奏。

R2′把这种业务规律转化成机器可验证契约。

------------------------------------------------------------------------

# 2. 业务来源

SRP 原始计划验证发现：

1524 家门店全部满足：

    合同
    +
    相位
    +
    星期模式

推导出的规律。

最终确认：

合同类型：

    周访

    双周访
        +
    phase φ ∈ {0,1}

因此：

月内拜访次数不是独立输入。

它是：

    合同 κ
    +
    相位 φ
    +
    自然周结构

共同推导出来的结果。

# 3. R2′ 的形式定义

每个门店 c 有三个层面的自由度：

## 3.1 星期重新分配

允许：

    Monday → Thursday

但必须整店生效。

------------------------------------------------------------------------

## 3.2 合同槽位选择

同一个星期几内部：

例如：

    Thursday:
    W1
    W3
    W5

具体日期由：

- 合同类型 κ；
- phase φ；

共同决定。

------------------------------------------------------------------------

## 3.3 合法日期域

形式：

    legal_date_map(
        contract,
        dates
    )

合法槽位：

    contract_slot_dates(
        κ,
        φ,
        slots
    )

# 4. 双周合同与 Phase

R2′最容易被误解的地方：

双周不是：

    每两周随便找一天

而是：

    固定节拍
    +
    固定 phase

例如：

phase = 0：

    W1 Tue ✓
    W2 Tue -
    W3 Tue ✓
    W4 Tue -

phase = 1：

    W1 Tue -
    W2 Tue ✓
    W3 Tue -
    W4 Tue ✓

所以：

双周门店的频次来自合同节拍，而不是一个独立 frequency 参数。

# 8. 不要混淆的三个概念

## R2′ 主线

    整店换星期几
    +
    合同槽位轮换

合法。

------------------------------------------------------------------------

## 任意跨日移动

例如：

    月初周一
    月底周四

不属于 R2′。

这是合同违约实验。

------------------------------------------------------------------------

## same_weekday_only

这个只能保证：

    weekday 不变化

不能保证：

    phase 合法

因此：

    same weekday
    ≠
    R2′ contract compliant

------------------------------------------------------------------------

# 9. W53 边界问题

ISO 周号不是业务本体。

问题：

    ISO week mod 2

在 53 周年份可能发生 parity 断裂。

正确方向：

定义连续周锚点：

\[ phase(d)= (weekStart(d)-anchorWeek)/7 \]

原则：

    anchor phase = ontology

    ISO week number = representation

ISO 周号只用于展示和输入映射。

------------------------------------------------------------------------

# 10. 工程不变量

必须保证：

## 合同决定节奏

不能：

    先决定日期
    再解释合同

应该：

    合同
     ↓
    合法日期域
     ↓
    优化选择

------------------------------------------------------------------------

## 次数不是独立变量

特别是双周门店：

    frequency

是：

    κ + φ

的派生结果。

------------------------------------------------------------------------

## 算法不能绕过契约

任何：

- ALNS
- SP
- BP

输出结果都必须通过：

    check_r2prime
