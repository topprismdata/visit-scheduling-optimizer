## 0. 为什么要 v4（问题起源）

v1（评估耦合 ALNS）、v3（反馈耦合 ALNS）都能大幅降里程（09 线 −9.6%、02 线 −25.6%），但本质相同：

> **把 SRP 计划只当"起点集合"，用 SA 大范围拆建，输出一版和原计划差异很大的新计划。**

业务上不成立：
1. **改动本身有成本**：换一家店的拜访日，业代要重新熟悉路线、客户要重约档期、考核口径要重算——不"免费"。
2. **业务员习惯是资产**：星期几锁定、片区认知是长期沉淀，一次性推倒等于扔资产。
3. **决策可解释性**："面目全非"的方案难通过评审；"只挪这 5 家店，省 63 公里"才可执行。

因此 v4 目标从 `min 里程` 改为：

> **`min (里程 + λ × 改动量)`，输出与现计划最接近、但确有收益的优化版。**

λ 的业务含义：**"每挪一家店，至少要省下 λ 公里才值得动"**。

## 1. 算法族谱（调研支撑）

"在现有结果上调整"是一整个有名字的算法族，工业界标准做法：

| 算法族 | 机制 | 代表文献 |
|---|---|---|
| **Re-optimization / Disruption Management** | 输入=已承诺计划，目标含"改动成本"项 | Ritzinger & Puchinger《A survey on dynamic and stochastic VRP》 |
| **Consistent VRP (ConVRP)** | 客户"哪天被访、谁访"跨期尽量不变 | **Groër, Sandholzer, Pisinger (2009)《The Consistent Vehicle Routing Problem》Transport Science**（奠基） |
| **Warm-start** | 现有解喂求解器继续精修，不重建 | LKH `INITIAL_TOUR_FILE`/`MERGE_TOUR_FILE`；CP-SAT `AddHint` |
| **Incremental Local Search** | 只做 2-opt/Or-opt/段移动，保留其余 | ILS+ALNS 耦合（2024-2025 主流） |
| **Change-cost / stability objective** | 目标显式放 `dissimilarity(new, incumbent)` | MDPI《VRP with Uncertainties》(2025) |

**共识**：规划系统默认在现解上局部改善；"里程↔改动"是多目标 Pareto 权衡；冷启动全重解触发 nervousness（计划抖动），现代综述明确要抑制。

## 2. 数学模型

### 2.1 记号
- 工作日集合 `T`（09 线 |T|=23）；门店 `V`（163 店）；每店月频次 `f_i`
- **现计划（incumbent）**：`X⁰`，`(i,t)∈X⁰` 表示店 i 第 t 天被访，每店 `f_i` 次
- **新计划**：`X`，同样满足每店 `f_i` 次
- 单日成本 `C_t(X)` = 第 t 天最短开放 TSP 里程（暖启动）
- **改动量** `Δ(X) = #{i : X 给 i 的日期集合 ≠ X⁰ 给 i 的}`（被挪动的店数）

### 2.2 目标

```
min_X  Σ_t C_t(X)  +  λ · Δ(X)
       └─ 总里程 ─┘     └改动店数┘
```

约束（业务不变）：每店月频次 = `f_i`（`count_ok`）；星期几锁定（v4 默认只允许换到**同星期几的不同周次**）；每日店数无硬上限。

### 2.3 λ 两种用法

| 模式 | 含义 | 解读 |
|---|---|---|
| **A. 收益门槛** | 每挪一店要省 > λ 公里 | λ=10：只有省超 10km 的挪动被采纳 |
| **B. 改动预算** | 最多挪 k 家店 | 拉格朗日式，二分 λ 使 Δ≤k |

λ=0 退化为 v3；λ→∞ 退化为"不动日分配、只做每日顺序"。**λ = 效率↔稳定旋钮**。

## 3. 算子与接受准则

### 3.1 起点 = 现计划（不重建）
`tours[t]` = 现计划第 t 天店序列（暖启动）。

### 3.2 "最小有益"局部算子

| 算子 | 描述 | Δ改动 |
|---|---|---|
| **day-shift** | 店 i 从周次 ta 挪到同星期几另一次 tb | +1 |
| **pair-swap** | 同星期两店互换周次 | +2 |
| **Or-opt（日内）** | 一天内移一段改善顺序，**不换日** | **0** |
| **ejection-chain（受控）** | 挪 i 致 j 被动挪，深度≤2 | +1~2 |

### 3.3 接受准则（改动感知）
```
gain(m) = Δ里程(m) − λ · Δ改动数(m)
接受当 gain(m) > 0（或 SA: exp(gain/T)）
```
- 日内 Or-opt：Δ改动=0 → 省里程就收（"免费"改善）
- 跨日 day-shift：省里程需 > λ 才收（"值回票价"）

### 3.4 输出：改动清单 `changes.csv`
| 客户编码 | 原周次 | 新周次 | 单店里程收益 | 是否跨星期几 |
一眼看到"动了哪几家、为什么动、值不值"。

## 4. 与 v1 / v3 的关系（复用非另起）

| | v1 评估耦合 | v3 反馈耦合 | v4 增量重优化 |
|---|---|---|---|
| 起点 | 计划(重解) | 计划(重解) | **计划(就地调)** |
| 目标 | min 里程 | min 里程 | **min 里程 + λ·改动** |
| 接受 | 只降 | SA(无成本) | **SA + 改动成本** |
| destroy 强度 | 大 | 大(SISR 级) | **极小(day-shift 优先)** |
| 与现计划相似度 | 低 | 中 | **高(λ 控制)** |

v4 在 v3 骨架（warm two_opt / tour-carrying / SA）上仅加：①改动计数器 Δ；②接受公式 −λ·Δ；③算子换成"最小有益"族；④输出改动清单。**是 v3 的目标函数扩展，不是新链**。λ=0 时 v4≈v3，保留 v3 作自由优化上限。

## 4.5 通用定位：它是精修层，不是第 4 个求解器

v4 的输入是**任意来源的一个解** + **一个参照锚点 + λ**，做"在起点上用最小有益调整继续改善"。v1 / v3 / Ensemble SP / SDR / 业务员手工版 / 上月已执行计划都可作起点：

```
任意算法输出 X ┐
SRP 原始计划  ─┼─► v4 通用精修器 (start + incumbent + λ) ─► X*  (里程近最优 + 对现计划扰动最小)
手工/历史计划 ─┘
```

**关键澄清（否则通用会退化）**：λ 惩罚的改动量 Δ 必须**相对参照解 X⁰（现计划）计算，而非相对起点 start**。否则把"已大改过的 v3 输出"再喂进来时，往 v3 附近挪都算"免费"，稳定性失控。

- **起点 start**：任意（决定从哪开始下降）
- **锚点 incumbent**：固定通常是 SRP 现计划（决定 Δ 往哪对齐）
- v4 输出天然落在一条 **"里程 ↔ 对现计划扰动" 的 Pareto 前沿**上，λ 是沿线的旋钮：λ=0 贴 v3（里程最低、扰动最大）；λ→∞ 退回"只优化每日顺序、不换日"。
- 因此 v4 **包住所有求解器**：v3 是"λ=0 特例"，原始计划是"λ=∞ 起点"。

## 6. 验证计划（实现后回填实测）

1. **λ 扫描** {0,5,10,20,50}：画 Pareto 曲线（x=改动店数，y=里程）。λ=0 应≈v3(262.5)；λ↑→改动↓、里程↑、每改动省的公里↑。
2. **同改动预算对照 v3**（如≤15 店）：v4 里程应优于"v3 截断改动"。
3. **可解释性**：每条改动单店收益>λ，无"为省 0.1km 换一天"碎动。
4. **多规模**：09 线 + 02（大线）+ 11（小线）。

## 7. 风险与边界（诚实声明）

- 星期几强锁 → 跨星期几收益被禁 → 里程改善小于 v3；放宽则改动感更强。用 λ + `same_weekday_only` 把选择权交业务。
- 只微动 → 局部最优风险高于 v3；SA + 有限重启缓解，但 v4 本就不追求全局最短里程——**追求性价比**。
- 单日成本 `C_t` 每次评估需 TSP；v4 改动小可增量 2-opt，仍比 v1 便宜、比 v3 频繁，预算内实测。
