# V4 重设计：多目标帕累托方案生成器（MO-ALNS）

> **项目**：SRP 拜访计划优化引擎 · V4 重设计  
> **定位**：不是后处理器，而是独立的多目标求解器——输入原始计划 + 约束偏好，输出帕累托前沿上的一组多样化方案  
> **日期**：2026-09-03 · 设计稿 v2  

---

## 1. 为什么旧设计有问题

旧 V4（v1 设计稿）把 V4 定位为"后处理器"：拿 v3 的解往回退，只解决"和原始计划的一致性"。这太窄了。

客户真正需要的不是"退回多少"，而是在**四个互相冲突的目标**之间做出知情决策：

| # | 目标维度 | 含义 | 业务翻译 |
|:---:|---|---|---|
| f₁ | **总里程** | 骑行总公里数 | "省多少油钱" |
| f₂ | **改动量** | 相对原始计划被挪动的店数 | "业代要适应多少变化" |
| f₃ | **均衡度** | 每日拜访量的方差/极差 | "有没有哪天特别累" |
| f₄ | **走廊连贯性** | 同一天跨街区的次数 | "路线是否顺路不折返" |

这四个目标**互相冲突**：
- 里程最优 → 需要大量跨日移店 → 改动量大
- 改动最少 → 不动日分配 → 里程只能靠日内重排
- 均衡度最优 → 强制平摊 → 可能拆散地理聚集的店 → 里程变差
- 走廊连贯最优 → 集中清扫某片区 → 可能某天特别多店 → 均衡度变差

**没有任何单一方案能在四个维度上同时最优**。V4 的价值就是找到这条帕累托前沿，让客户在上面选一个点。

## 2. 重设计：V4 = MO-ALNS（多目标自适应大邻域搜索）

### 2.1 架构

```
输入:
  - 原始计划 X⁰ (SRP 店→日分配)
  - 路网距离矩阵 D
  - 地理围栏 zone_of (走廊归属)
  - 约束: 每店月频次 f_i, 星期几锁定

输出:
  - 帕累托前沿上的 K 个非支配解 {X₁, X₂, ..., Xₖ}
  - 每个解标注四维指标 (f₁, f₂, f₃, f₄)
  - 自动推荐 3~4 个命名方案（激进型/推荐型/均衡型/保守型）
```

### 2.2 算法框架：NSGA-II + ALNS 混合

```
初始化:
  Population P = {X⁰(原始), TSP(X⁰), v3(X⁰), 贪心回退中间点, 随机扰动解}
  |P| = N (50~100)

主循环 (每代):
  1. 非支配排序: 将 P 按 Pareto 支配关系分层 (F₁, F₂, ...)
  2. 拥挤度计算: 同层内按目标空间距离排序，保留分布均匀的解
  3. 环境选择: 截断至 N 个
  4. 生成子代:
     a. 从 P 中选 parent（锦标赛，偏好非支配+拥挤度低）
     b. 对 parent 施加 ALNS 算子:
        - destroy: worst-edge removal / segment removal / random removal
        - repair: regret-2 insertion
     c. 子代加入 P
  5. 重复直到时间预算耗尽

输出:
  非支配解集 = Pareto 前沿近似
```

### 2.3 四个目标的精确计算

```python
# f₁: 总里程（与 v3 相同）
f1 = Σ_t day_km(tour_t, D)

# f₂: 改动量（相对原始计划）
f2 = #{i : dates_X(i) ≠ dates_X⁰(i)}

# f₃: 每日工作量均衡度（变异系数 CV，消除规模影响）
counts = [len(tour_t) for t in T]
f3 = std(counts) / mean(counts)   # CV ∈ [0, +∞), 越小越均衡

# f₄: 走廊连贯性（跨区边占比）
cross_edges = #{(u,v) ∈ tour_t : zone(u) ≠ zone(v)}
total_edges = Σ_t (|tour_t| - 1)
f4 = cross_edges / max(1, total_edges)  # ∈ [0,1], 越小越连贯
```

### 2.4 为什么不用加权标量化

加权标量化（`min w₁f₁ + w₂f₂ + w₃f₃ + w₄f₄`）的问题：
1. 权重难以解释（"λ=2.5 是什么意思？"）
2. 无法找到非凸帕累托前沿上的解
3. 需要大量运行不同权重组合才能覆盖前沿

NSGA-II 的优势：
1. 一次运行产出整条前沿
2. 非支配排序天然处理多目标冲突
3. 拥挤度机制保证前沿解的多样性（不会全部挤在一个角落）

## 3. 输出方案命名

从帕累托前沿中自动选取 4 个代表点：

| 方案名 | 选择规则 | 业务含义 |
|---|---|---|
| **激进型** | f₁ 最小的非支配解 | "里程最省，但改动大" |
| **推荐型** | 膝点（knee point）：距理想点最近的解 | "均衡了四个目标的最优点" |
| **均衡型** | f₃ 最小的非支配解 | "每天工作量最均匀" |
| **保守型** | f₂ 最小的非支配解 | "几乎不改日程" |

## 4. 与 v3 的关系

v3 仍然存在，但角色变化：

| | v3 | V4 (MO-ALNS) |
|---|---|---|
| 目标 | 单目标：min km | 多目标：Pareto(f₁, f₂, f₃, f₄) |
| 输出 | 1 个解 | K 个非支配解 |
| 前沿位置 | 帕累托前沿的一个端点（f₁ 最小端） | 整条帕累托前沿 |
| 业务角色 | "如果你只在乎里程，这是极限" | "如果你在乎多个维度，这里有整套选择" |

v3 的解自动包含在 V4 的初始种群中，作为 f₁ 方向的种子。

## 6. 诚实声明

1. **NSGA-II 在连续 15 秒预算内**可能无法完全收敛到真正的帕累托前沿——产出的解集是前沿的**近似**
2. **走廊连贯性**（f₄）依赖地理围栏质量；如果 zone 划分不合理，f₄ 可能产生噪声
3. 四个目标的帕累托前沿在 4 维空间中可能是**曲面**而非曲线，用 2D 图表只能投影展示其中 2~3 个维度
4. **膝点（knee point）的自动检测**在高维空间中没有完美算法，本实现使用到理想点欧氏距离最小作为启发式
