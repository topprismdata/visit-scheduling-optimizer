# 多目标帕累托稳定器设计（Pareto Stabilizer，原 V4）

> **状态**：评审整改版 v3.1 · 2026-09-05（逐条落实外部评审 P1-2 / P1-3 / P2-7）  
> **定位**：以显式基准解为锚，在其邻域内演化，输出帕累托前沿上一组多样化命名方案（激进/推荐/均衡/保守）  
> **当前契约唯一性**：本文档只描述**三目标**（f₁/f₂/f₃）与**双向走廊约束**；历史四目标（含 f₄ 走廊连贯性）设计稿已废止，见 §7。

---

## 1. 业务问题

客户需要的不是单一"最省里程"方案，而是三个互相冲突目标之间的知情决策：

| # | 目标 | 含义 | 业务翻译 | 计算 |
|:---:|---|---|---|---|
| f₁ | 总里程 | 全月骑行公里数 | "省多少运力" | `Σ_t day_km(tour_t, D)` |
| f₂ | 改动量 | 相对**显式基准 `base`** 被挪动日期的店数 | "业代要适应多少变化" | `#{c : dates_X(c) ≠ dates_base(c)}` |
| f₃ | 均衡度 | 每日门店数变异系数 CV | "哪天特别累" | `std(counts)/mean(counts)` |

冲突关系：里程最优⇒大量挪店⇒改动大；改动最小⇒只能日内重排；均衡最优⇒可能拆散地理聚集⇒里程变差。**无单一方案三者同时最优** → 输出整条前沿供选择。

> **f₄（走廊连贯性）为何废止**：其 zone 围栏概念源自 Clustered TSP 场景，该场景经实测证伪（路边店强扫街 +14.6% 纯损失，见 `docs/archive/deprecated/V4_DESIGN_v1_DEPRECATED.md` 与 `docs/guides/ALGORITHM_GUIDE.md` §5.7），且 f₂ 已覆盖"改动量"这一业务真正关心的稳定性维度。**与 Layer 2 在途 street-corridor 顺路插单是两个无关概念**，勿混淆。

## 2. 硬约束与可行性契约（评审 P1-2 / P1-3 整改核心）

本求解器**只能**在满足以下约束的解空间内演化，违反任一约束的候选解在**进入非支配排序之前**即被丢弃：

| 约束 | 定义 | 校验落点 |
|---|---|---|
| C1 月频次守恒 | 每店次数 = 计划行数 f_c | 扰动算子结构性保持（先摘后插）；输出校验 `freq_ok` |
| C2 同日去重 | 同一日不得出现同店两次 | `_feasible()` 逐日 `len(set(seq))==len(seq)` |
| C3 双向作业走廊 | 每日店数 ∈ [K_min(l), K_max(l)] | `_feasible()` 逐日上下界检查；所有算子（move/swap/perturb）**生成期即检查目标日不越上界、来源日不越下界** |

### 2.1 `base` 契约（消除口径漂移）
- `base` 是**显式传入参数**：默认应为**上游已走廊合规的排历结果**（走廊约束版路径反馈 ALNS 或列生成终解器的输出），或降级为原始计划 `data.days_orig`；
- f₂ 的参照**永远**且**只有** `base`，由 `ref_dm = _dates_map(base)` 固定一次，全程不得与 `data.days_orig` 混用；
- 若 `base` 本身违反 C2/C3，`_feasible()` 过滤后前沿为空 → **显式抛错**（"请先以走廊约束版产出合规基准"），杜绝静默把违规基准当锚点继续放大（评审 P1-3 原缺陷：旧实现直接继承上游不合规 base，且扰动未排除同日重复与越界）。

### 2.2 星期几语义
主线保持每店原星期几（SRP 系统"固定日拜访计划"字段，数据 100% 成立），改动仅在**同星期几跨周次**内发生。跨星期几实验由总设计 §10-2 的开关单独评估，不与本模块主线混用。

## 3. 算法：NSGA-II 环境选择 + ALNS 邻域算子

```
输入: data(含 min/max_daily_capacity), D, base(合规锚点), extra_seeds(如基线A锚点), 预算
初始化: P = { base, base日内2-opt, 从base走廊内合法扰动×k }
每代:
  1. 非支配排序(NUM_OBJ=3) → fronts
  2. 同层拥挤度计算
  3. 截断至 pop_size
  4. 子代生成: 锦标赛选父代 → 施加 [worst_move|random_move|swap|oropt]
       · 所有跨日 move/swap 在施加前检查 C2+C3（目标日未满 & 来源日高于下限）
  5. 子代过 _feasible() 门禁后才加入种群
终止: 预算耗尽 → 合并进化解 + extra_seeds 锚点(独立保全不被截断淘汰)
      → _feasible() 过滤 → 非支配排序 → 取 F1 去重
命名: aggressive=min f1 | conservative=min f2 | balanced=min f3 | recommended=距理想点最近(欧氏归一)
```

**为什么 NSGA-II 而非加权标量化**：加权法权重无解释力、无法触达非凸前沿、需多次跑；NSGA-II 单次产出整条前沿，拥挤度保证解多样性。

## 4. 与上游求解器的关系

| | 路径反馈大邻域搜索 | 列生成终解器 | **帕累托稳定器（本模块）** |
|---|---|---|---|
| 目标 | min 里程（单目标） | min 里程 + RMP-LP 池内差距 | Pareto(f₁,f₂,f₃) |
| 输出 | 1 个高质解 | 1 个前沿近似最优解 + 差距证书 | K 个命名方案 |
| 基线 A 定位 | 相对基线 A 的降幅 | 同上 + 池内证书 | **把降幅与改动量的兑换摆上台面** |
| 角色 | 主力生成器 / 本模块锚点 | 终解器 | 客户交互选点层 |

基线 A = 原计划分配 + CP-SAT 日内最优排序（全办 4,144.3 km，09 线 326.6 km，见 `output/cpsat_plan_baselines.json`）；f₂ 的最小端（"保守型"即改动≈0）在里程上必然收敛于基线 A，可用作实现自检。

## 6. 诚实声明

1. 有限时间预算内产出的解集是前沿的**近似**（NSGA-II 未必收敛到真前沿）；
2. 膝点检测在 3 维无完美算法，以到理想点欧氏距离为启发式；
3. f₂/f₃ 存在权衡耦合（CV 下降可能靠大量挪店实现），解读时应同时看三个维度而非单点；
4. 走廊上下界与 CV（f₃）部分冗余：走廊已硬卡极差，CV 主要刻画"是否贴近走廊中位"而非单纯极差——这是刻意保留的两个独立视角，非设计缺陷。
