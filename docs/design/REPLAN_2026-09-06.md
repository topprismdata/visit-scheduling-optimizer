## 2. 四阶段计划

### Phase A：合同本体落地（代码层，本机 M2 + 远程同步）
**目标**：本体从文档进入代码，09 线单线端到端验证。
1. `core/metric.py`：`contract_of(c, dates)`（从 SRP 反解 κ,φ）、`contract_slot_dates(κ,φ,σ,dates)`、`check_contract(days, ...)`；
2. `algos/r2_alns.py`：MOVE 合法目标 = 合同槽位集（每店每 σ′ 恰 1 个候选日期集，全组合枚举删除）；奇相位双周店禁跨槽位类换挡；
3. `algos/sp_matheuristic.py`：覆盖等式右端 → 派生次数；z 约束保留；
4. `AlgoResult` 增 `contract_ok` 字段；
5. **验收**：原始计划过 `check_contract` 零违例（1,524 家）；09 线 r2_alns 单跑产出 contract_ok=True 的解池。
**依赖**：无。**风险**：r2_alns 搜索空间收窄（每店 MOVE 目标从 C(k,f) 个降到 ≤5 个 σ′×1），需观察收敛性。

### Phase B：旧账相位审计（只读，可与 A 并行）
**目标**：量化旧终账的相位污染面。
1. 十线终解逐店扫描：每店日期集 vs 合同槽位集，统计相位违例店数（分合同类型）；
2. 168 家换店明细：跨槽位类换挡家数（预期 0，因 count_ok 锁死 f）、同 σ 内相位错位数；
3. 产出 `output/contract_audit_r2_ledger.json` + 审计小节（进 TWO_STAGE_BENCHMARK_REPORT 附录）。
**依赖**：A.1 的 `check_contract` 原语。**预期**：若违例集中在少数店，Phase C 增量收拢；若大面积污染，十线全量重跑。

### Phase C：合同口径重跑（Windows 28 线程为主力）
**目标**：出合同本体严格口径的正式账。
1. 09 线 3-rep 先行（对照旧 310.4/313.9，预期持平或微升——约束只会更紧）；
2. 十线终账 v2（`output/sp_contract_ledger_all.json`），刷新宪法 §四；
3. 消融复跑：静态 SP vs CG 在新口径下是否仍差值≈0（池肥度变化后重验）。
**依赖**：A 全部 + B 结论。**拍板点（用户）**：① 双周店相位可否翻转（默认否）；② 奇相位店跨槽位类换挡是否放开（默认禁）。
