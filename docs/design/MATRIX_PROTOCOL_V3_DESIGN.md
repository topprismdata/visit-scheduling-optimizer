> **状态**：草稿 v0.2 · 2026-09-07（待老板评审；评审通过后转实施计划）
> **实施计划**：评审通过后另出（估计器下沉 = 剥离计划 Task 4-6，为前置件）

## 1. 背景

### 1.1 业务背景

本引擎服务的不是单一客户：**不同客户的门店分布（clustered/random）、密度、数量（20~200+ 店）、调整频率（插单率）、对速度的要求各不相同**。因此生产系统里不存在单一最优算法——老板裁定（2026-09-07）：**保持不同算法的独立性与多样性，按客户场景路由引擎**（portfolio 模式，参照美团场景化调度、菜鸟多 VRP 变体引擎）。

现有生产资产：10 条真实线路（OSRM 路网实测矩阵）+ 两层求解架构（Layer1 日历搜索 → Layer2 单日 TSP → Contract-SP 集合划分终闸）+ 5 个日历引擎（base 构造式、alns_v3、hgs_pvrp、sp_cg、r2_alns）与 Branch-and-Price（bp），TSP 档位 nn2opt / cpsat / lkh3。

### 1.2 问题背景（v2 矩阵为什么不干净）

现有 4×3 矩阵（`contract_matrix_cell/v2`）为"生产选型快筛"设计，拿来做**算法研究对比**时经三遍设计评审落实三个实锤：

1. **格间不独立**：每格池混入基线保底列，弱引擎被稀释成 ≈0%，无法区分"无贡献"与"SP 选了基线列"。
2. **bp/r2 构造性同源**：bp 模式偷吃 R2′ seed 列（池 ⊇ R2′），10/10 线逐线相等是构造必然，不是算法结论。
3. **池表示脏**：`dedupe_pool` 按精确序列去重、每店集保留 8 条排序——同一组合选择的多副本撑大池（线 11 池 1,449 列），reroute 耗时口径失真。

伴随的**算法定位混乱**（评审深挖发现）：bp 被当第 N 个启发式排名（范畴错误——它是精确框架，primal 侧从不是卖点）；ALNS 同族三变体冗余占格（实测全部 ≈ 基线）；SDR 老零件（老版 SP/LP）与新一代组件职责重叠。

### 1.3 业界参照

| 来源 | 吸收的机制 |
|---|---|
| 美团配送 | 仿真回放 + 多维 KPI 记分卡 + "假设→指标→离线预评估→A/B→发布"闭环 |
| 菜鸟 | SINTEF/CVRPLIB 受控实例族打榜；LaDe 工业级真实数据集；真实约束赛题 |
| 学术 | Uchoa et al. 2017 受控维度实例设计（规模/分布/需求系统化交叉） |

### 2.1 主目标

### 2.3 成功标准

## 3. 设计原则（5 条，各有出处）

| # | 原则 | 出处 |
|---|---|---|
| 1 | **类别代表制**：按算法类别保代表，同族变体不重复占格 | ALNS 族 3 格实测 ≈ 基线（变体无增量的实证） |
| 2 | **独立性协议**：每格裸池（引擎自足、格间零交叉）；bp 自带日历搜索热启动 | 老板独立性哲学；评审 P3/P5 |
| 3 | **双尺子**：元启发式量 **km 画像**；bp 量**证书画像**（gap/证完率）——不同类别不同尺，禁止混排 | 算法分类学：B&P 是精确框架（Barnhart 1998 [BARN]），oracle 弱则退化为 matheuristic with bound reports，primal 侧从不是卖点 |
| 4 | **受控实例族 + 真实切片** | 菜鸟 CVRPLIB 打榜模式、Uchoa 2017 受控维度；美团分场景评估 |
| 5 | **多维 KPI 记分卡**，不报单一总分 | 美团配送仿真沙箱 KPI 体系 |

## 4. 算法类别定位（身份卡）

| 引擎 | 类别 | 算法身份 | 独有产物 | 矩阵尺子 |
|---|---|---|---|---|
| `base` | 构造式 | 原分配 + CP-SAT 日内精排 | 参照系（业务现状最优排序） | km 画像（分母） |
| `r2_alns` | **元启发式 → 合同同构 SLS** | 搜索空间与业务自由度同构（整店换星期几 + 槽位轮换，`move_candidates(combo_mode="contract")`），移动即合法、结果即台账；单算子 + 贪婪 + 5% 扰动；搜索期零求解器 | 高质量 + 业务可解释 + 逐位可复现的日历列 | **km 画像主力** |
| `sp_cg` | LP 列生成 | 对偶驱动列生成，产 RMP 下界 | 下界 + 对偶 | km + 下界 |
| `bp_solo` | **精确框架（未完成态）** | 节点 LP（子树真下界）+ Ryan-Foster 分支；oracle 弱则按文献退化为 matheuristic with bound reports；primal 侧从不是卖点 | **全局 gap 证书**（全场唯一） | **证书画像** |
| `r2+bp` | **组合格**（供列→框架） | 流水线上下游组合，明码标价 | 协作增量（见 §6 剖面③） | 组合增量 |

- **边界裁定**：bp 与 r2 不在同一类别（primal 搜索器 vs 界机器），"同源"是工程接线偶然；bp_solo km ≈ 基线是诚实画像，禁止解读为"bp 无用"。
- **同族降级**：alns_v3 / hgs_pvrp 降为变体实验，不进主矩阵。

## 5. 组件关系与测试分层（独立测 vs 组合测的尺子）

**SP 是终点站，不是竞争者**——它不产生任何东西，池里有什么才能选什么；所有算法的本质都是"给 SP 供列"。**CG 是一种供列技术**：LP 对偶指出"最缺什么列"，定价子问题专找它；sp_cg 是 CG 的完整实现，bp 是"分支树 × 每节点 CG"。

| 算法 | 与 SP 关系 | 与 CG 关系 |
|---|---|---|
| base / r2_alns / alns_v3 / hgs | 供列 | 不用对偶（廉价盲搜） |
| sp_cg | 自身就是 SP 在跑 | CG 本尊 |
| bp_solo / r2+bp | 每分支节点内嵌 SP-LP | 每节点跑一次 CG |

**测试分层三规则**：
1. **同岗位（互为替代）→ 独立测**：各自裸池、各比各的画像，禁止合池比总分——合池稀释是 v2 病根。
2. **流水线上下游（供列→终闸）→ 组合测**：所有格共享**同一个 SP 终闸协议**（组合的形态是"共享终闸"，不是"合并格池"）；引擎间唯一合法组合格 = r2+bp，报协作增量。
3. **算法内生零件 → 单元测**：CG 定价器（`test_mathmodel_sp_contract` 已有）、bp 节点 LP/分支（B&P 7 用例已有）——拆开是组件，合上是算法，不另设格。

## 6. 完整矩阵组合（D1-D4 × 三剖面）

**维度**：
- **D1 引擎格**：base / r2_alns / sp_cg / bp_solo / r2+bp（组合格）；旁路变体：alns_v3 / hgs
- **D2 TSP 档**（效果-速度四点谱）：`nn2opt → multistart-NN2opt（SDR 思想）→ cpsat → lkh3（大规模）`
  - **SDR Exact 处置**：多起点 TSP 采样思想降为谱上策略行（"穷人版精确 TSP"）；其老版 SP（无合同闸）被统一 Contract-SP 终闸取代；其 LP 下界被 sp_cg 覆盖。SDR 整体不再作独立格——日历=原分配不动、cpsat 排序已日内最优，必然与 base 打平（实测 0.9s 收敛、gap=0 印证）。
- **D3 预算档**：r2 迭代 {25K, 100K, 360K} × seed {1, 4}；sp_cg 两档；bp oracle `exact_tl {0.5, 1, 5}s`
- **D4 实例**：真实 10 线 + 合成 ~32（C1）

**三剖面**（按问题组织，不做全笛卡尔）：

| 剖面 | 组合 | 规模 | 回答的问题 |
|---|---|---|---|
| ① 主剖面（质量，必跑） | 5 格 × cpsat × 标准预算 × 42 实例 | ~210 runs | 各引擎裸池真实质量；适用域地图主体 |
| ② 速度剖面 | r2/sp_cg/bp_solo × {nn2opt, multistart, lkh3} × 快预算 × 抽样 8 实例 | ~48 runs | 质量-速度取舍曲线；n 增大时哪档撑得住 |
| ③ 机制曲线 | bp_solo × exact_tl 档；r2 × seed 边际 | ~126 runs | 证书-预算曲线；seed 边际收益 |

**记分卡字段**（每 run）：`km_recomputed, vs_base_pct, seed方差, wall_sec, iters, 三闸通过, 逐位复现一致`（全引擎）＋ `root_lb, gap_pct, converge_proven率`（bp 系）＋ `增量列数, 增量列被选率`（r2+bp 组合格）。

**效果-速度取舍显式编码在三个轴**：D2（路线质量 vs TSP 时间）、D3（搜索深度 vs 墙钟）、D4-n 维（规模场景）——每张记分卡是取舍平面上的一个点，切片报告即取舍曲线族。

**预算估算**（同机 Apple M2）：主剖面 ≈ 7-9h；机制曲线 r2 seed 边际 ≈ 7h；全量一次完整扫描 ≈ 2 个通宵；快筛档（主剖面 × 抽样 12 实例）一晚。

## 7. 组件设计

### C1 实例层
- **真实线**：现有 10 线（OSRM 实测矩阵）——生态效度锚点。
- **合成实例族生成器**（新增模块，四维受控）：规模 n ∈ {20, 50, 100, 200}；空间密度 clustered/random；合同混合比 周访:双周 = 3:1 / 1:1；调整频率扰动率 0% / 5% / 15%。交叉采样 ≈ 24-36 实例；确定性、实例带版本戳、自带距离矩阵与合同表。

### C2 引擎层
每格裸池协议：池 = 仅本引擎产出；预算 = 同 seed 集 + 显式迭代预算；墙钟单独记录（**速度是画像维度，不是控制变量**）。

### C3 池规范化层
- 全局统一：`(date, 店集)` 唯一 + 该店集**最优排序一条**（同组合选择禁止多副本）。
- 边界：裸池不可行 = 合法记分卡行（`INFEASIBLE`）；超时 = `TIME_LIMIT` 行；**任何格禁止回退注入基线列**——安全网只存在于生产编排层。

### C4 评估层
双尺子记分卡见 §6；`sp_solve_ip`（r2_prime + contract）为全格统一终闸，`check_contract/capacity` 独立复验。

### C5 报告层
- 分场景切片表：按 n / 密度 / 合比 / 扰动率分位，不报单一总分。
- 适用域地图 → 回填 `ALGORITHM_GUIDE` 附录 E。

## 8. Schema 与兼容

- 新 schema `research_matrix/v1`：引擎、实例戳、列来源戳、画像各维。
- 旧 4×3（`contract_matrix_cell/v2`）**保留**，定位"生产选型快筛"（含基线安全网正是其生产语义）；两协议并存、文档分工明确。v2 不回填来源戳。

## 9. 测试守卫

1. 池独立性：格间池交集为空（来源戳断言）。
2. 规范化幂等：`normalize(normalize(p)) == normalize(p)`。
3. 生成器确定性：同 seed 逐位一致；维度覆盖抽样断言。
4. 双尺子隔离：bp 格禁止产出 km 改进声明；元启发式格禁止产出证书声明。
5. 合成实例冒烟：n=20 全引擎跑通（协议连通性）。

## 10. 风险与边界

- 弱引擎裸池大面积 INFEASIBLE：合法研究发现（量化其对基线列的隐性依赖），非协议缺陷。
- bp_solo km ≈ 基线：按定义即预期（价值在证书画像）。
- 合成实例与真实分布的差距：真实线切片做生态效度锚点；两套报告分开呈现。
- ESPPRC 未落地前 bp 证书画像只能报 BOUND_HEURISTIC 档——诚实记录；oracle 升级是 bp 身份成立的生命线路线图。
