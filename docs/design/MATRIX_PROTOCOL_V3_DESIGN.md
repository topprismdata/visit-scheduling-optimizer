# 矩阵协议 v3 设计：算法研究对比协议（Research Matrix v1）

> **状态**：草稿 · 2026-09-07（待老板评审；评审通过后转实施计划）
> **缘起**：老板对 4×3 矩阵"不干净"的直觉，经三遍设计评审落实为三个实锤：①格间不独立（每格混基线保底列，弱引擎被稀释成 ≈0%）；②bp/r2 构造性同源（bp 池 ⊇ R2′ seed 列，10/10 逐线相等是必然不是结论）；③池表示脏（`dedupe_pool` 按精确序列去重、每店集留 8 排序，同组合选择多副本撑大池——线 11 池 1,449 列，reroute 耗时口径失真）。
> **定位裁定**（老板 2026-09-07）：生产系统不存在最优算法——客户门店分布/密度/数量/调整频率/速度要求各异，**保持算法的独立性与多样性**，按场景路由引擎。矩阵目的从"选冠军"改为"**给每个算法画能力画像，产出适用域地图**"。
> **实施计划**：评审通过后另出（估计器下沉 = 剥离计划 Task 4-6，为前置件）。

## 1. 设计原则（5 条，各有出处）

| # | 原则 | 出处 |
|---|---|---|
| 1 | **类别代表制**：按算法类别保代表，同族变体不重复占格（ALNS 族 3 格实测 ≈ 基线，印证变体无增量） | 纯算法定位分析 |
| 2 | **独立性协议**：每格裸池（引擎自足、格间零交叉）；bp 用自带日历搜索热启动，不吃 R2′ 列 | 老板独立性哲学；评审 P3/P5 |
| 3 | **双尺子**：元启发式量 **km 画像**；bp 量**证书画像**（gap/证完率）——不同类别不同尺，禁止混排 | 算法分类学：B&P 是精确框架（Barnhart 1998 [BARN]），oracle 弱则退化为 matheuristic with bound reports；其 primal 侧从不是卖点 |
| 4 | **受控实例族 + 真实切片**：合成实例生成器按维度系统刻画 + 真实线分位切片 | 菜鸟 SINTEF/CVRPLIB 打榜模式、Uchoa et al. 2017 受控维度；美团分场景评估 |
| 5 | **多维 KPI 记分卡**：质量/速度/鲁棒/合规/确定性，不报单一总分 | 美团配送仿真沙箱 KPI 体系（发单回放 + KPI 预评估 + A/B 闭环） |

## 2. 算法类别定位（各引擎的身份卡）

| 引擎 | 类别 | 算法身份 | 独有产物 | 矩阵尺子 |
|---|---|---|---|---|
| `base` | 构造式 | 原分配 + CP-SAT 日内精排 | 参照系（业务现状最优排序） | km 画像（分母） |
| `r2_alns` | **元启发式 → 合同同构 SLS** | 搜索空间与业务自由度同构（整店换星期几 + 槽位轮换，`move_candidates(combo_mode="contract")`），移动即合法、结果即台账；单算子 + 贪婪 + 5% 扰动；搜索期零求解器 | 高质量 + 业务可解释 + 逐位可复现的日历列 | **km 画像主力** |
| `sp_cg` | LP 列生成 | 对偶驱动的列生成，产 RMP 下界 | 下界 + 对偶 | km + 下界 |
| `bp_solo` | **精确框架（未完成态）** | 节点 LP（子树真下界）+ Ryan-Foster 分支；oracle 弱则按文献退化为 matheuristic with bound reports；primal 侧从不是卖点（B&P 定位） | **全局 gap 证书**（全场唯一） | **证书画像** |

- **边界裁定**：bp 与 r2 不在同一类别，"同源"是工程接线偶然；研究矩阵中 bp **自足**（自带日历搜索热启动），km ≈ 基线是其诚实画像，禁止解读为"bp 无用"。
- **同族降级**：alns_v3 / hgs_pvrp 降为"变体实验"，不进主矩阵。
- **hybrid（bp + R2′ 列）**移出研究矩阵，保留为生产编排选项（`--bp-hybrid`）。

## 3. 组件设计

### C1 实例层
- **真实线**：现有 10 线（OSRM 实测矩阵）——生态效度锚点。
- **合成实例族生成器**（新增模块，四维受控，对应客户差异维度）：
  - 规模 n ∈ {20, 50, 100, 200}
  - 空间密度：clustered / random（仿 Uchoa C/R 维度）
  - 合同混合比：周访:双周 = 3:1 / 1:1
  - 调整频率：月内插单扰动率 0% / 5% / 15%
  - 交叉采样 ≈ 24-36 实例；确定性（seed 可复现）、实例带版本戳、自带距离矩阵与合同表。

### C2 引擎层
每格裸池协议：池 = 仅本引擎产出；预算 = 同 seed 集 + 显式迭代预算；墙钟单独记录（**速度是画像维度，不是控制变量**）。

### C3 池规范化层
- 全局统一：`(date, 店集)` 唯一 + 该店集**最优排序一条**（同组合选择禁止多副本）。
- **格间零交叉守卫**（测试）：列来源戳（`source ∈ {base, engine, pricing}`）断言格间交集为空。
- 边界：裸池不可行 = 合法记分卡行（`INFEASIBLE`）；超时 = `TIME_LIMIT` 行；**任何格禁止回退注入基线列**——安全网只存在于生产编排层。

### C4 评估层（双尺子记分卡，每引擎 × 每实例）
| 画像 | 指标 | 适用 |
|---|---|---|
| km 画像 | `sp_km_recomputed` vs base、多 seed 方差、裸池可行率 | base / r2_alns / sp_cg |
| 证书画像 | root_lb 紧度、`converge_proven` 率、gap 随 oracle 预算曲线 | bp_solo |
| 速度画像 | 墙钟随 n 曲线、迭代吞吐 | 全部 |
| 合规/确定性 | 三闸通过率、同 seed 重跑逐位一致率 | 全部 |

### C5 报告层
- 分场景切片表：按 n / 密度 / 合比 / 扰动率分位，不报单一总分。
- **适用域地图**：哪个类别引擎在哪个象限赢 → 回填 `ALGORITHM_GUIDE` 附录 E，把"不存在最优算法"变成可执行的客户→引擎路由规则。

## 4. 数据流

```
实例族生成器 ──┐
              ├→ 引擎裸跑（独立协议）→ 池规范化 → 双尺子记分 → 切片报告 → 适用域地图
真实 10 线  ──┘
```

## 5. Schema 与兼容

- 新 schema `research_matrix/v1`：引擎、实例戳、列来源戳、画像各维。
- 旧 4×3（`contract_matrix_cell/v2`）**保留**，降级为"生产选型快筛"（含基线安全网正是其生产语义）；两协议并存、文档分工明确。v2 不回填来源戳。

## 6. 测试守卫

1. 池独立性：格间池交集为空（来源戳断言）。
2. 规范化幂等：`normalize(normalize(p)) == normalize(p)`。
3. 生成器确定性：同 seed 逐位一致；维度覆盖抽样断言。
4. 双尺子隔离：bp 格禁止产出 km 改进声明；元启发式格禁止产出证书声明。
5. 合成实例冒烟：n=20 全引擎跑通（协议连通性）。

## 7. 风险与边界

- 弱引擎裸池大面积 INFEASIBLE：合法研究发现（量化其对基线列的隐性依赖），非协议缺陷。
- bp_solo km ≈ 基线：按定义即预期（价值在证书画像）；不得解读为"bp 无用"。
- 合成实例与真实分布的差距：真实 10 线切片做生态效度锚点；两套报告分开呈现，不混算。
- ESPPRC 未落地前 bp 证书画像只能报 BOUND_HEURISTIC 档——诚实记录；oracle 升级是 bp 身份成立的生命线路线图。
